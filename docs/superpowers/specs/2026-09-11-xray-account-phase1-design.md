# Xray 账户管理：第一阶段设计

日期：2026-09-11。状态：用户通过“确认设计文档”批准本设计，采用文档中的默认方案；功能尚未开始实现。文中明确保留的技术验证和后续细化项仍须完成，设计批准不代表运行能力已经验证。本文件补充 `docs/xray-account-handoff.md`，以最新第一版范围作为验收依据。

## 已确认的约束

- 在当前 3x-ui 单仓库扩展，复用 Go/Gin/GORM 后端及 React/Ant Design 界面。
- 兼容 v2rayN、v2rayNG、Shadowrocket、Clash，不假设用户同意开发或安装配套客户端。
- 使用现有 VLESS + REALITY。Clash 的验收对象须是支持该协议组合的实现；建议选用 Mihomo 内核版本并在兼容测试时记录具体版本。
- 第一版目标是普通用户账户、账户流量汇总、共享月额度及用户界面。
- 第一版包含两台代理服务器，预计全系统 20 个账号、20 人同时使用；需要双节点流量汇总及共享额度的实际验收。人数是容量目标，不作为注册数、设备数或连接数上限。
- 管理员可以在列表中多选一批账户，实时批量修改其流量额度；这是用户已确认的第一版能力要求。
- 用户明确表示“第一版不考虑控制同时在线设备数”。设备身份识别、在线名额、第 11 台拒绝及自助移除设备不属于第一版开发或验收范围；不预建相关表和会话服务。
- 不用 IP 数、配置数、连接数、注册次数或订阅 HWID 上限替代已移出的设备限制，也不修改无关的既有代理设置。

## 已确认的四项业务规则

2026-09-11 用户明确要求将这四项写入设计，作为第一版实现与验收要求。

1. **额度恢复**：新周期开始或管理员提高额度后，自动按当前周期已用量重新计算可用状态。有剩余额度时解除“额度耗尽”停用；管理员手动停用的账户保持停用，提高后仍无剩余额度的账户不恢复。恢复必须经运行时执行，页面区分处理中、成功和失败。
2. **流量口径**：用量按上传加下载计算，同一账户所有关联配置使用同一倍率累计到共享月额度。保留上下行及合计数据，额度输入和用量显示明确标注单位；不能混用 GB 与 GiB 或重复应用倍率。
3. **用户界面**：第一版包含登录、用量与剩余额度、连接配置、修改密码。普通用户仅可访问自己的配置和数据；账户因额度耗尽停用代理后，仍可登录查看用量及状态。
4. **密码与代理凭据分开**：修改网页登录密码不自动更换代理 UUID，不触发代理配置重置。配置泄露后的代理凭据重置另设独立操作；界面明确区分两类操作，凭据重置不得清零账户用量或增加额度。

凭据重置的操作者权限、覆盖范围和旧连接处理属于独立操作的后续细化内容；本次确认不等于授权自动重置全账户配置，也不恢复已移出第一版的设备管理要求。

## 双节点范围与规模验收

用户已确认两台代理服务器、预计 20 个账号和全系统 20 人同时使用。第一版需要覆盖下列跨节点行为：

- **统一账户和额度**：两台服务器上归属同一账户的所有用量累计到同一月周期。按统一计量口径，节点 A 用了 30 GiB、节点 B 用了 50 GiB，则账户已用 80 GiB；若账户额度为 100 GiB，则全账户剩余 20 GiB。
- **节点来源与去重**：保留计量来源，分别采集两个节点的增量再合并；同一 UUID 在不同节点上的实际流量都要计入。重复上报只去除同一来源的重复增量，不能丢掉另一个节点的真实用量。
- **跨节点停用和恢复**：额度耗尽、管理员停用、提高额度或新周期恢复时，向该账户关联的所有节点执行相应状态，验证两边的新连接与已有连接，保持其他账户可用。
- **实时批量调整**：20 个账户的批量操作按账户及关联节点报告执行进度和失败，不以某一个节点成功代表整个账户已生效。
- **异常可见**：覆盖一个节点失联、重启、恢复上报和执行失败。失联节点不能显示已执行成功，恢复后按最新目标状态同步；数据缺口不能被当作用量为零。失联时继续服务还是限制服务及容忍时长，仍需在连接控制设计中确定，本次容量确认不构成这项策略的确认。

采用一个统一管理端维护账户及月用量账本，通过现有 `runtime.Runtime` 管理两个代理节点。管理端是否与其中一台代理服务器同机在部署阶段决定；两台代理的规模要求不自动增加第三台服务器或引入新的分布式服务。

规模验证使用 20 个独立测试账号持续产生真实代理流量，覆盖两节点分散使用及集中使用一节点、同一账户两节点同时使用的场景；在负载期间执行批量调额并观察用户界面和节点状态。记录硬件、带宽、核心/客户端版本、连接数、实际吞吐、采集延迟和停用/恢复耗时。20 人同时使用不等于只建 20 个 socket，也不代表已承诺每人的带宽或系统吞吐；具体流量模型和时延目标随原型验证细化。

## 设备控制的历史结论（第一版范围外）

Xray 的 VLESS 用户认证依据 UUID；3x-ui 当前 HWID 检查读取订阅 HTTP 请求的客户端自报字段。两者之间没有当前已验证的、不可被配置复制绕过的物理设备绑定。

同一 UUID/配置复制到两台设备后，在同一个 NAT 出口建立连接，服务端无法仅凭该凭据和 IP 可靠证明这是两台物理设备。一个真实设备也可同时建立大量连接。因此，在通用客户端使用可复制凭据的条件下，单独修改面板不能保证原要求。

| 路线 | 能做到的事 | 对当前要求的影响 |
| --- | --- | --- |
| 仅按 IP、连接数或订阅 HWID 限制 | 对某些共享/异常使用进行限制 | 不能作为真实在线设备上限，排除作为完整实现 |
| 每份设备配置分配独立凭据，并由连接层管理这些凭据的会话 | 区分凭据的用量、单独撤销凭据；连接层仍需验证 | 配置被复制时仍不能保证真实设备数，不能未经用户同意改称满足 10 台要求 |
| 引入能够提供设备证明的客户端配合与连接层认证 | 为严格设备准入提供实现基础 | 增加客户端和协议接入工作，尚未获得此范围的授权 |

用户已选择第一版只实现下述账户、流量和月额度范围。历史设备要求是否恢复后续另行确定，不再阻塞第一版交付；界面不得展示未经验证的“在线设备数”或“设备限制已生效”。额度耗尽时的账户连接控制仍属于第一版，不能与设备限制一起移出范围。

## 第一阶段用户流程

1. 管理员在现有管理界面创建普通用户，设置初始密码、月额度和账户状态，关联该账户可使用的代理客户端配置。
2. 普通用户登录独立的用户区域，只能看到自己的连接配置、上传/下载/合计用量、当月剩余额度、结算周期和账户状态，并可修改自己的密码。
3. 代理客户端继续通过标准链接或订阅导入 VLESS + REALITY 配置。
4. 一个账户下的所有关联凭据共享同一额度；例如账户配置 100 GiB，总和达到 100 GiB 即进入额度耗尽状态，不按凭据数量增加额度。
5. 额度耗尽或管理员停用后，账户关联配置进入禁止使用的目标状态；后台经运行时接口执行，并展示执行成功、处理中或失败，不能把数据库更新等同于节点已执行。
6. 新月创建新结算周期并解除“额度耗尽”导致的停用；管理员主动停用的账户继续保持停用。
7. 管理员在账户列表勾选多个账户，通过“批量修改月额度”提交变更，查看每个账户的额度保存和实际生效结果。
8. 用户修改网页登录密码时保持原代理 UUID；配置泄露时通过独立的代理凭据重置流程处理。

第一阶段不增加设备数量限制、设备会话/踢下线页面或自研客户端。开放注册、邮箱供应商、支付和套餐售卖不纳入本设计。

## 管理员多选批量调整额度

采用以下批量操作规则；实现时按共享账户额度和逐节点执行结果验收。

- **选择与提交**：账户列表支持勾选多行和全选当前页，显示已选账户数；批量弹窗列出所选账户、原月额度、当月已用量及新额度。只操作明确选中的账户，不把当前筛选结果隐式扩展成全库操作。
- **修改方式**：第一版先提供“统一设置为 X GiB/月”，更新账户的月额度设置并用于当期和后续周期，直到再次修改。不是把 X 当作额外赠送流量；按差额增减或仅本月临时加量不自动纳入本次需求。
- **计量保留**：修改额度不重置累计或当月用量，不重置结算周期，不更换 UUID。一个账户的全部关联凭据继续共享一份额度；未选账户保持原额度。
- **提高额度**：保存后立即按最新已用量重新判断。只有原来因额度耗尽停用、且新额度足够的账户进入恢复流程；管理员手动停用的账户不自动恢复。
- **降低额度**：已用量达到或超过新额度时，立即触发该账户的停用流程；剩余额度显示为零，实际已用量完整保留。
- **实时语义**：提交后立即保存设置并触发运行时调整，不等待下个自然月、用户重新登录或客户端重新下载订阅。目标账户的新连接和已有连接均受额度规则约束；节点实际完成存在延迟，必须通过实测给出验收范围，不承诺同步零延迟。
- **结果和重试**：逐账户显示保存成功/失败及运行时处理中/已生效/失败。部分失败时保留成功结果，允许重试失败项；重试不重复增加额度、不清零用量，并按最新额度及用量执行，不能让旧请求覆盖后续调整。
- **权限和记录**：仅管理员可调用批量接口，服务端逐项校验账户及输入；记录操作人、时间、账户、修改前后额度和执行结果。普通用户只能看到自己的最新额度和状态。

示例：A 已用 80 GiB，B 已用 150 GiB，将二者月额度统一设为 100 GiB 后，A 剩余 20 GiB，B 剩余 0 并进入停用流程；B 的已用量仍是 150 GiB。之后设为 200 GiB，两者分别剩余 120 和 50 GiB，是否恢复还需检查管理员停用状态。

现有 `frontend/src/pages/clients/ClientsPage.tsx` 和 `ClientBulkAdjustModal.tsx` 提供代理客户端的多选批量操作交互，可参考其组件模式。现有 `bulkAdjust` 按代理客户端传入 `addBytes`；新账户功能需要更新共享月额度，不直接把每个关联 `ClientRecord` 都设置成一份完整账户额度。

## 模块与数据归属

- **账户模块**：新增普通用户身份及账户归属，管理员 `User` 继续用于管理端。普通用户登录态与管理端隔离，服务端逐请求检查资源归属及账户状态；网页登录密码修改不触发代理凭据轮换。
- **配置关联模块**：一个账户可关联多个 `ClientRecord`，同一代理凭据只能归属一个账户。优先保留原代理配置；关联已有配置不自动轮换全账户 UUID。已有关联的凭据如需转移账户，必须先结算旧归属并建立新的计量起点。
- **计量模块**：将同一账户的代理上下行数据按统一倍率汇总到统一月周期，金额/支付不在此模型中。持久化字节数和计量来源，避免把同一个 Xray 用户统计重复计入多个入站或重复应用倍率。
- **额度模块**：支持管理员单账户及多选批量调整共享月额度，区分管理员停用、额度耗尽和节点执行失败。代理变更统一通过现有 `runtime.Runtime`，不从控制器绕开它直调 Xray。
- **用户界面**：复用组件、样式及多语言机制，提供用户登录、概览、连接配置与账户安全页面。用户 API 和实时消息都要按归属过滤，不能向普通用户开放管理员全量 WebSocket。

## 第一阶段默认规则

用户批准设计后，采用下列默认值和工程约束：

- 账户由管理员创建；密码只能重置，不能查看明文。
- 月周期按 UTC 自然月，界面明确显示周期起止时间；数据库存整数 byte，界面单位使用 GiB（1 GiB = 1,073,741,824 byte）。上传加下载，关联配置使用同一倍率。
- 现有代理配置关联账户时，从启用账户计量的时点开始记入当月额度，不虚构此前未知的月用量。
- 后台流量更新与账户用量更新需共享事务或具有明确的持久化去重机制；不能由浏览器计算计费值，也不能靠前端定时请求驱动计量。
- 已有流量清零、进程重启、采集失败、重复上报及月切换分别测试；手动重置代理统计不能同时抹掉账户的历史月结算记录。
- 沿用现有单节点与远程节点运行时边界；第一版双节点及跨节点共享额度已经确认，必须完成对应集成验证，单节点测试通过不能代替。

## 实施前先验证的两项技术风险

**用量记账可靠性**：现有 `XrayTrafficJob.Run` 从核心读取统计后调用 `InboundService.AddTraffic`。源码显示 `XrayAPI.GetTraffic` 以 `Reset_: false` 读取累计值，并在返回增量前推进内存基线；这不能证明后续数据库写入失败时仍能恢复未入账增量。实施前验证数据库失败如何重试、远程节点是否重复上报，以及核心重启时如何识别计数器世代。设计不能承诺在数据源没有提供的范围内无损恢复流量；采集异常需要可见。

**额度执行及已有连接**：现有流量任务支持在禁用客户端后选择重启 Xray。全核心重启会影响其它账户，不能当作正常的按账户断流方案。必须以选定 Xray 版本验证：禁止新连接、定向终止目标账户已有 TCP/UDP/Mux 会话，以及其它账户连接保持。若现有 API 不支持，需要先提交连接层扩展方案，不能只修改 `Enable` 就宣称额度已严格执行。

轮询统计存在检测与执行延迟；达到阈值后仍可能产生少量额外流量。第一阶段需测出并披露该延迟和超用行为，不承诺字节级硬上限。若要求严格硬上限，需要额外设计节点本地预算和断流机制。

## 安全与实施顺序

1. 建立隔离的本地开发与测试环境，验证固定 v3.7.0 基线能构建。仅使用临时测试数据及本地监听，不接触现有生产代理。
2. 核对既有审查中与本阶段入口相关的安全问题和上游修复，逐项以回归测试验证；安全修复单独提交。未解决的部署风险继续保留在审查记录中。
3. 先在双节点路径验证上述记账与定向停用风险，再确定账户计量的数据写入点和节点执行方案。
4. 实现普通用户认证、归属校验、管理员管理接口及数据库迁移。
5. 实现账户计量、共享月额度、管理员批量调整、月切换及节点执行状态。
6. 实现用户页面及客户端导入验收，最后执行双节点端到端回归和 20 个账号并发使用的规模验证。

## 第一阶段验收

- 用户 A 无法读取/修改用户 B 的账户、用量、链接或实时消息；普通用户不能调用管理员接口。
- 新身份和关联表迁移不改变既有管理员、入站及未关联代理用户的行为；迁移可重复运行。
- 两个不同凭据的流量准确汇总到同一账户，重复采样不会重复加账，多入站共享凭据不会重复计量。
- 在相同倍率下，上下行之和经一次倍率换算后计入共享额度；不同关联配置计量一致，页面额度及用量单位明确且数值转换一致。
- 核心/节点重启、统计重置、数据库失败和月切换均有可解释且经测试的处理结果。
- 同一账户在两台节点同时使用时准确汇总用量，保持一份共享月额度；重复上报不重复累计，不误去重另一节点的真实流量。
- 两台节点的停用/恢复及批量调额均有执行证据；一台失联或失败时可见，恢复后执行最新状态并验证用量处理，其他账户不受影响。
- 在两台代理服务器、20 个测试账号并发使用时完成采集、额度控制和用户界面端到端验证，记录实际负载及耗时，不能仅以单元测试或空闲连接数宣称容量验收通过。
- 用量耗尽后验证连接路径的实际阻断效果、延迟及是否影响其他账户；失败状态可见，不能报告虚假的执行成功。
- 新周期或提高额度后，有可用额度的账户解除额度耗尽状态，提高后仍无余额则保持停用；管理员手动停用不被自动解除，用户不能修改自身额度或重置用量。
- 用户可完成登录、查看本人用量与剩余额度、获取本人连接配置、修改密码；额度耗尽后仍可访问用户界面，不能越权读取其他账户数据。
- 修改网页登录密码前后代理 UUID 保持一致；代理凭据重置必须由独立操作触发，并保持账户已用流量和额度设置，不能因重置获得额外流量。
- 管理员多选后只修改选中账户的共享月额度；当月用量和周期保持不变，重试不会产生额外额度或覆盖更新的设置，普通用户请求批量修改被拒绝。
- 批量提高/降低额度分别验证恢复和停用，管理员手动停用保持；部分失败按账户显示并可重试。节点未执行成功不能显示“全部已生效”。
- v2rayN、v2rayNG、Shadowrocket、支持 VLESS + REALITY 的 Clash/Mihomo 实现，逐个记录实际版本、配置导入和真实连接验收证据。没有测试设备时明确标记未验收。
